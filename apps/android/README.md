# KS Light for Android: build and release

Flutter app for direct Bluetooth control of KS lights, with optional hub mode. User documentation: [docs/ANDROID.md](../../docs/ANDROID.md).

- Package ID: `dev.kslight.ks_light`
- Version: set in `pubspec.yaml` (`1.2.1+6` at the time of writing)
- Minimum Android: 7.0

## Toolchain

Use the versions pinned in [`.github/workflows/android.yml`](../../.github/workflows/android.yml): Flutter 3.47.5 (revision `6a19cca56475dbfba1478ee68d7bd0c2ef891da1`), JDK 21, Android SDK platforms 35 and 36, build-tools 36.0.0 and NDK 28.2.13676358. Run `python -m ks_light.build_toolchain` from the repository root before Gradle; it checks the pinned Gradle wrapper and platform tool hashes recorded in `release/android-toolchain.json`.

Gradle dependency verification is strict (`android/gradle/verification-metadata.xml`). See [RELEASE_CHECKLIST.md](../../docs/RELEASE_CHECKLIST.md) for updating it.

The pinned `flutter_reactive_ble` plugin emits a Kotlin Gradle plugin migration warning. Keep the pinned toolchain until a plugin migration is tested.

## Build and test

From this directory:

```sh
flutter --no-version-check pub get --enforce-lockfile
flutter --no-version-check analyze --no-pub
flutter --no-version-check test --no-pub
flutter --no-version-check build apk --debug --no-pub
```

Native shortcut tests, from `android/`:

```sh
./gradlew :app:testDebugUnitTest      # gradlew.bat on Windows
```

Dart-to-Python hub contract smoke, from the repository root:

```sh
python -m apps.android.tool.smoke_hub --dart PATH_TO_DART
```

Tests read shared fixtures from `protocol/`; keep the checkout layout intact. `--no-version-check` avoids a background SDK tag fetch.

Documentation screenshots are generated by `tool/capture_screenshots.dart`; see [docs/images/README.md](../../docs/images/README.md).

## Release signing

Release builds require a private `android/key.properties` (copy `android/key.properties.example`). There is no fallback to the debug key, and a fresh checkout has no signing credentials. Never commit keys, passwords, `key.properties` or symbol files.

Public APKs are signed with this certificate (SHA-256). Verify downloads against it:

```text
37:E0:15:4E:39:EB:91:9D:6A:66:C6:E1:57:CF:C1:91:F4:D3:37:AD:53:41:78:06:29:23:CE:02:F2:F6:52:62
```

All public updates must use the same key. The maintainer keeps the keystore and password offline; they are never uploaded to GitHub or CI. CI signs only with a disposable key to check that release assembly works; those APKs are never published.

### Release build

In a clean checkout of the reviewed commit, with `android/key.properties` in place:

```sh
flutter --no-version-check clean
flutter --no-version-check pub get --enforce-lockfile
```

Add this entry to the `packages` array of the generated `.dart_tool/package_config.json`. It maps Flutter's generated plugin registrant to a logical package URI so no local machine path is compiled into the APK. Do not commit the generated file.

```json
{"name":"ks_light_build","rootUri":"flutter_build/","packageUri":"","languageVersion":"3.13"}
```

Then build:

```sh
flutter --no-version-check build apk --release --no-pub --build-number=BUILD --obfuscate --split-debug-info="$PRIVATE_SYMBOLS_DIR" --extra-gen-snapshot-options=--strip
```

`PRIVATE_SYMBOLS_DIR` must be outside the checkout; keep the symbols for crash diagnosis ([Flutter obfuscation guide](https://docs.flutter.dev/deployment/obfuscate)). Delete `android/key.properties` afterwards. Before publishing, check package ID, version code, non-debuggable status, certificate, and the absence of local paths or credentials, then record asset hashes.

## Moving between signing keys

Android cannot update an app signed with a different key. Moving from a self-built or development-signed install to the public APK requires uninstalling, which deletes app data:

1. **Library backup > Export backup file** to save rooms and scenes. This is not a full backup.
2. Separately note light names, default light, color balance, saved colors, effect presets, appearance, widget setup and hub pairing.
3. Uninstall, install the new APK, rescan lights, import the backup with **Match backup devices**, and restore the remaining settings by hand.
